# Guide memory and stream recovery — 25 October 2026

Version 0.9.8-preview / code 20 reduces guide residency to the visible three-hour window plus navigation margin and the live now/next window. Full schedules remain in SQLite; asynchronous indexed-channel search queries that database rather than the UI cache. A check using the actual 59,916-record catalogue loaded 8,524 records (85.8% fewer); future programme search and literal-percent matching were preserved. This is a record-count reduction, not a measured device RAM reduction.

The hourly publisher now includes a small exact-channel source inventory in status.json, so the existing publication workflow distributes it without any workflow permission changes. Successful run 40187300964 published 1,645 native routes for 1,047 channels. The client fetches this independently of guide/artwork on source exhaustion and periodically while playing; replacement keeps alternatives and retries changed addresses. Up to three backup feeds are sampled every five minutes after a 15-second settling delay, through the device VPN. Paused playback skips checks. Healthy playback is never forcibly replaced. These are manifest/media reachability probes, not a guarantee of decoded picture and sound on every channel, nor a whole-catalogue nightly playback audit.

Build, JVM unit tests, Android lint, and 68 catalogue tests passed. Additional SQLite validation used the exact Room query against the published catalogue.
